# ORBITAL WAR

Мобильный браузерный PvP-прототип космической стратегии для двух игроков. Клиент работает в браузере, комнаты и боевая симуляция обслуживаются Node.js-сервером с Socket.IO.

## Что уже реализовано

- Настоящие комнаты на сервере с пятизначным кодом и лимитом ровно в два игрока.
- Создание комнаты, подключение по коду, отмена ожидания и обработка заполненной/несуществующей комнаты.
- Идентификатор игрока хранится в `localStorage`: при кратком обрыве или перезагрузке клиент пытается вернуться в свою комнату.
- Окно переподключения — 30 секунд. Неожиданное отключение не завершает матч мгновенно; по истечении времени не вернувшийся игрок получает техническое поражение.
- Сервер authoritative: энергия, покупки, апгрейды, производство, движение, столкновения, атаки, снаряды, урон и результат матча рассчитываются на сервере.
- Команды имеют `requestId` и кэшируются для защиты от повторного выполнения. Добавлен лимит команд в секунду.
- Клиент получает персональный снимок состояния. В нём есть только собственная база игрока; модель, координаты, уровень, ресурсы и модули противника не отправляются. Для верхней шкалы HUD отдельно передаются только HP противника и максимум HP.
- Снимки отправляются примерно 10 раз в секунду, серверная симуляция работает с частотой 20 тиков в секунду. Положение кораблей плавно интерполируется на Canvas.
- Три типа кораблей с разными ролями: истребитель ведёт огонь по базе с дистанции, бомбардировщик наносит урон тараном, перехватчик останавливает и атакует вражеские корабли. Очередь производства — до пяти заказов, есть лимит флота, пушка, лазер, энергогенератор и ускоренный ангар.
- Четыре слота на первом уровне, шесть на втором и восемь на третьем. Модули визуально встроены в корпус базы.
- Энергия: 200 на старте, генерация 5/с, лимит 1000. Реактор добавляет 3/с.
- Победа/поражение и повторный матч по согласию обоих игроков.
- Адаптивный вертикальный интерфейс, обработка касаний, безопасные области экрана, звуковые переключатели и полноэкранный режим (при поддержке браузером).

Игра с ботом запускает отдельный серверный матч: бот использует тот же игровой движок, экономику, производство и боевую симуляцию, что и сетевой соперник.

## Требования

- Node.js 18 или новее (рекомендуется актуальная LTS-версия).
- npm, который устанавливается вместе с Node.js.
- Современный браузер на телефоне или компьютере: Safari на iPhone, Chrome/Firefox на Android или настольный браузер.

### Установка Node.js

Откройте официальный сайт Node.js: <https://nodejs.org/>. Установите LTS-версию для своей операционной системы. После установки проверьте:

```bash
node --version
npm --version
```

## Запуск на компьютере

Распакуйте проект, откройте терминал в папке `ORBITAL-WAR` и выполните:

```bash
npm install
npm test
npm start
```

После запуска откройте в браузере:

```text
http://localhost:3000
```

Проверка доступности сервера:

```text
http://localhost:3000/health
```

Публичная конфигурация для интерфейса (цены и параметры, не являющиеся секретами):

```text
http://localhost:3000/api/config
```

Остановить сервер можно сочетанием `Ctrl+C`.

### Проверка на двух телефонах в одной Wi-Fi-сети

1. Подключите оба телефона и компьютер, на котором запущен сервер, к одной Wi-Fi-сети.
2. Узнайте локальный IP-адрес компьютера. Например, `192.168.1.25`.
   - Windows: `ipconfig`.
   - macOS: `ipconfig getifaddr en0` (для Wi-Fi; интерфейс может отличаться).
   - Linux: `hostname -I`.
3. Разрешите входящие подключения к TCP-порту `3000` в локальном firewall компьютера.
4. На обоих телефонах откройте `http://192.168.1.25:3000` (подставьте свой IP).
5. На первом телефоне нажмите «Сетевая игра» → «Создать комнату».
6. На втором нажмите «Сетевая игра» → «Присоединиться к комнате» и введите пятизначный код.
7. Когда второй игрок войдёт, сервер автоматически начнёт матч.

`localhost` на телефоне указывает на сам телефон, а не на компьютер. Поэтому на обоих телефонах нужно использовать LAN-IP компьютера.

## Игра через интернет

Чтобы два человека подключались из разных сетей, сервер должен иметь публичный адрес. Самый простой вариант — развернуть Node.js-проект на облачной платформе или VPS.

### Вариант A: облачная платформа для Node.js

1. Загрузите проект в свой Git-репозиторий.
2. Создайте на выбранной платформе новый Node.js/Web Service из репозитория.
3. Укажите команду установки: `npm install`.
4. Укажите команду запуска: `npm start`.
5. Платформа должна передавать приложению переменную окружения `PORT`. Сервер слушает `0.0.0.0` и использует этот порт.
6. Включите поддержку WebSocket-соединений. Socket.IO также имеет polling fallback.
7. После успешного деплоя платформа выдаст публичный HTTPS-адрес. Откройте его на обоих телефонах и создавайте комнату обычным способом.

Если платформа отдельно задаёт CORS-политику, установите `CORS_ORIGIN` в список origin-адресов клиентского сайта через запятую. Если сайт и сервер раздаются этим же приложением с одного домена, дополнительная настройка обычно не требуется.

### Вариант B: VPS и обратный прокси

На VPS установите Node.js LTS, скопируйте проект, затем:

```bash
npm install
NODE_ENV=production npm start
```

Для постоянной работы используйте менеджер процессов (например, systemd или PM2). Не открывайте игровой сервер в интернет без HTTPS-терминации. Рекомендуемая схема:

```text
Телефон -- HTTPS/WSS :443 --> Nginx -- HTTP :3000 --> Node.js
```

Пример минимального блока Nginx (замените домен и пути сертификатов):

```nginx
server {
    listen 443 ssl http2;
    server_name game.example.com;

    ssl_certificate     /etc/letsencrypt/live/game.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/game.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 75s;
    }
}
```

После настройки DNS и сертификата публичный адрес будет `https://game.example.com`. Оба игрока открывают один и тот же адрес. Socket.IO автоматически использует защищённое WSS-соединение поверх HTTPS.

### Docker (необязательно)

В корне проекта уже есть `Dockerfile`. Он копирует в контейнер клиент, сервер и `resources/` с текстурами:

```bash
docker build -t orbital-war .
docker run --rm -p 3000:3000 orbital-war
```

Для публичного размещения контейнер всё равно следует поставить за HTTPS reverse proxy или использовать платформу, которая выдаёт HTTPS-домен.

## Игровые правила прототипа

| Элемент | Параметры |
|---|---|
| База | 1000 HP |
| Энергия | старт 200, +5/с, максимум 1000 |
| Улучшение базы | уровень 2 — 300, уровень 3 — 700 |
| Баллистическая пушка | 100 энергии, 12 урона, перезарядка 1.8 с |
| Лазерная установка | 150 энергии, 18 урона, перезарядка 2.4 с |
| Энергогенератор | 120 энергии, +3 энергии/с |
| Ускоренный ангар | 180 энергии |
| Истребитель | 60 энергии, производство 3 с |
| Бомбардировщик | 110 энергии, производство 6.2 с |
| Перехватчик | 90 энергии, производство 4.5 с |
| Очередь производства | до 5 кораблей |
| Лимит флота | 30 кораблей на игрока |

Точные значения, урон, дальность и скорострельность находятся в `server/config.js`. Сервер — единственный источник цены и игровых характеристик; `/api/config` используется только для отображения значений интерфейсу.

## Сетевые события

Клиентские события:

- `room:create` — создать комнату.
- `room:join` — присоединиться или восстановить сессию по коду и токену.
- `room:cancel` — отменить ожидание в лобби.
- `room:leave` — покинуть комнату или сдаться в активном матче.
- `room:rematch` — запросить повторный матч.
- `game:command` — `install`, `upgrade` или `produce` с уникальным `requestId`.

Серверные события:

- `room:created`, `room:joined`, `room:error`, `room:closed`.
- `room:playerDisconnected`, `room:playerReconnected`, `room:rematchStatus`.
- `match:started`, `match:ended`, `game:state`, `command:result`.

Сервер не принимает от клиента координаты кораблей, здоровье, энергию, урон или признак победы.

## Проверки и ограничения текущей сборки

Автоматические проверки запускаются командой `npm test` и используют встроенный Node.js test runner. Текущие тесты проверяют осадное поведение истребителя, таран бомбардировщика, блокировку цели перехватчиком, зеркальную работу для обоих игроков и наличие `resources/` в Docker-образе.

JavaScript-файлы также проверяются командой `node --check`. После деплоя проверьте на телефонах производство, боевые роли кораблей, отображение текстур и обе полоски HP. Полный ручной тест мобильного браузера не заменяется автоматическими тестами.

Прототип рассчитан на один процесс Node.js и хранит комнаты/матчи в памяти. Перезапуск сервера удаляет активные матчи. Для production-масштабирования понадобятся внешнее хранилище комнат, sticky sessions или Socket.IO adapter, мониторинг, более строгая защита от злоупотреблений и нагрузочные тесты.
